# 问 TitoDex：结构化资料查询与答案约束

随 v0.9.17 发布，v0.9.18 延续；当前签名制品及源码证据见 [发布记录](RELEASES.md)。

针对“火岩鼠进化成暴鲤龙（Typhlosion）”这一实机错误，修复的对象是问答链路。已发布的 v20 包中，155 → 156 → 157 的关系及中文名称均正确，不需要为这一错误重发数据包。

资源接入不等于支持任意自然语言组合。当前反查按 AND 求交集；OR/排除条件要求拆开，避免悄悄忽略条件。目录中的任意效果条件还没有通用查询算子；例如“哪些树果治疗中毒”会明确说明未能执行该筛选，可指定条目查看已有说明。每页 24 个通用候选，招式最多四路并发检查该页；结果同时给出候选总数、检查数、匹配数和未知数，不能把第一页说成全部。单条回复保持 1200 字符上限，截断后保留部分结果提示。

## 最终答案如何受约束

`answerFromDexBundle` 统一接入结构化资源查询。直接查询的回答由程序生成，名称及实体按钮使用同一套稳定 ID。原有 v20 资料需要的在线检索仍可运行，但最终回答恢复执行过的结构化查询结果；支持另一段模型文本的引用不会被转贴为该结果的证明。

`enforceFinalFacts` 位于所有 compose、verify、双来源整理之后、语义分块之前。结构化结果不能被最后一次模型改写覆盖。没有直接查询结果的综合回答，也检查宝可梦、招式、特性和道具的中英文名称配对，以及本地完整进化图明确约束的肯定进化语句。它不是任意自然语言事实的完备证明器；开放问答不因此显示“已核验”。

接口新增可选 `evidence`，记录程序计算的资料依据、游戏/通用范围、是否完整、数据包版本、实体 ID 和候选总数。Flutter 保存该元数据到历史，结构化答案的按钮直接按 ID 解析。普通来源引用与结构化核对分开展示，旧记录没有这个字段时也不会仅凭置信度显示绿色核验结论。

进化关系与进化条件分开。v20 的通用条件包含跨版本合并的等级值；未确认当前版本时只显示关系和限制。无法确认地区形态时不套用普通形态。新增资源应采用固定路径、读取上限、规范 ID、明确范围和缺失数据回退，并补真实数据检查。

## 验证

在 `cloudflare/journey-assistant` 运行 `npm test` 和 `npm run test:structured`，并执行 TypeScript 检查。普通 Worker 测试池的文件系统是虚拟的，APK 资料检查使用独立 Node 配置。

准备真实包检查：在仓库根目录运行 `python tools/prepare_structured_query_audit.py releases/TitoDex-0.9.18-offline-rg-arm64.apk`，然后在 Worker 目录运行 `npm run test:structured`。可传 `--sha256` 校验指定制品。脚本只从现有 APK 提取固定 JSON 路径到忽略目录，不下载、不发布。

回归覆盖：原始火球鼠问题的 HTTP 路由、完整进化链、错误译名、模型复核错误通过、综合建议中的错误进化关系、版本缺失、分页、招式与特性交集、资源意图冲突、真实包结构、实体 ID 持久化、来源标签及原有回答动画/流式显示。v0.9.18 签名制品已发布并校验；实体设备覆盖范围仍单独记录，不由自动检查推定。
