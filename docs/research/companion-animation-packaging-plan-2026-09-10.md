# Companion 动画候选的打包与按需下载方案

日期：2026-09-10。依据当前 Flutter 候选界面、下载缓存代码及两轮素材调查整理。本文是实现方案，未将新清单加入 APK、修改产品代码或发布资源。

后续已在本地实现，最新行为及验证边界见 [实现说明](../COMPANION_ANIMATION_CATALOG.md)。实现采用“已映射且文件头可用的在线候选 + 首次下载时逐帧验证”，未预下载全套原图；下文保留最初方案供对照。

## 打包方式

APK 内置一份轻量、经过筛选的候选清单；每个动画保持独立 URL，用户选择并确认后下载该文件。Lite 与 Offline 使用同一份候选清单，新增高清动画都按需下载。已有内置小动画继续用于即时显示。

建议使用现有已声明的 `flutter/assets/data/` 目录，增加 `companion_animation_catalog.json`，打开 Companion 选择器时再加载并按物种建立内存索引。第一次接入不必同时升级 v20 图鉴包、增加独立资源 APK、全世代 ZIP 下载入口或新增远程清单服务。后续新增候选可以随 App 更新清单；已缓存动画不必重复下载。

体积测算：将当前 Paraíso 审计中 1,527 条已映射记录投影为物种、formKey、来源、颜色、URL、尺寸、大小、格式、验证状态字段，紧凑 JSON 为 **417,644 字节**，单文件 ZIP/Deflate 为 **31,216 字节**。这是清单的压缩测算，不是 APK 实际增量，也不代表这 1,527 条已通过全帧解码验收。原始审计报告包含重复证据，不直接打进 APK。

## 游戏代际与来源

沿用现有“动画来源”选择器，以“代际／游戏 · 来源 · 尺寸”显示候选。候选多时分组，不增加独立设置页。例如：

- `Gen VII · 究极之日／究极之月 · Paraíso`
- `Gen VIII · 剑／盾素材集 · Paraíso`
- `通用 · ShinyHunters · 560×510`
- 后续格式适配完成后可加入 `通用 · HOME · WikiDex`。

代际指动画对应的游戏或来源素材集，不能使用宝可梦的初登场世代。ShinyHunters 的原游戏尚未确认，先明确归入“通用”，不能因为大尾立是第二世代宝可梦就标成金／银动画。来源目录的游戏名称也不能证明该物种在该游戏里可获得；素材分组与玩法可用性分别处理。

## 清单结构

元数据分为来源表与资产表，避免每条记录重复长标签。每个普通色／异色文件独立记录，不依赖文件名推导另一颜色地址。

| 字段 | 用途 |
| --- | --- |
| `schemaVersion`、`catalogVersion` | 结构兼容与清单更新 |
| `assetId`、`revision` | 稳定候选身份与缓存版本 |
| `speciesId`、`formKey`、`gender` | 对齐本地图鉴的精确身份；来源内部编号另存 |
| `sourceId` | PokeAPI、Paraíso、ShinyHunters 等 |
| `gameVersionGroups`、`generation`、`provenance` | 游戏归属或“通用”；来源集名称与已确认游戏来源分开 |
| `shiny` | 此文件的颜色身份 |
| `url`、`format`、`width`、`height`、`frameCount`、`sizeBytes` | 下载与展示；真实格式不由后缀推断 |
| `sha256`、`verifiedAt` | 经过完整文件核验的发布清单校验值与时间 |

来源名称等展示文案接入现有中英文体系。运行时清单只收录已确认身份、实际多帧且能够播放的文件；未映射项、单帧 PNG、只检查了 GIF 文件头的记录保留在研究数据中，继续核验后再进入发布清单。

## 下载与缓存

1. 打开或滚动候选列表只读取清单，使用已有本地静态图／已缓存动画作预览，不触发整组高清文件下载。
2. 切换普通／异色时按精确身份过滤；相应颜色缺失就不提供该候选，不自动冒用另一颜色或默认形态。
3. 选择尚未下载的候选后，确认按钮显示下载动作与清单提供的大小；确认才下载所选颜色、形态的那一份。下载完成后切换到新动画，失败保留当前选择并允许重试。
4. 缓存以 `assetId + revision` 命名，校验大小／哈希后从临时文件原子替换。列表显示“已下载”，下次选择直接使用本地文件。
5. 现有资源管理页负责查看大小与删除缓存。删除正在使用的文件后可以回到本地预览并提示重新下载，不应在打开主页时静默重下大文件。

明确选择某个高清候选时，失败不能下载另一来源的小图后仍把该高清候选标成“已下载”。原有“自动”模式可以保留其既定回退行为，但不能与显式候选的下载成功状态混淆。

## 需要改动的现有位置

- `flutter/lib/widgets/companion_picker_sheet.dart`：现有 `_animationChoices` 合并新清单，按游戏／来源显示。当前预览会使用远程 URL，需要让尚未确认下载的高清候选只改变选择状态。对有精确 formKey 资产的形态，不能被现有“共享 species ID 禁止泛用动画”规则一并挡住。
- `flutter/lib/features/companion/companion_media.dart`：当前 GIF 缓存主要按媒体数字 ID 命名，显式选择新来源时可能复用旧小图；新增独立资产缓存与文件校验，不破坏旧缓存读取。
- `flutter/lib/features/companion/companion_repository.dart`：保存候选 `assetId`，兼容已有 URL 选择；新增可空字段时兼容旧偏好值。
- `flutter/lib/widgets/companion_standby.dart`：显式候选使用对应本地文件，普通／异色 URL 从清单读取；高清 3D 素材使用适合它的采样方式。已选素材缓存丢失时不自动拉取大文件。

## 来源进入发布清单的顺序

先处理 Paraíso 与 ShinyHunters 的准确映射和多帧核验，按文件加入已通过条目；现有 PokeAPI 候选继续可选。无需等待所有来源全部补齐才能发布，但不得宣称全形态覆盖。

WikiDex 的 WebM、FurretTurret 的 ZIP 均不是当前图片路径可直接消费的候选：前者需格式适配，后者需逐文件整理与来源核对，再决定单文件分发地址。本轮不为它们新增播放器或发布镜像。52Poké 继续遵守仓库现有已审计缓存的范围。

## 实现后的验收重点

用同一只宝可梦切换两种来源，验证不会读到旧缓存；普通／异色分别命中对应文件；共享物种 ID 的形态不串图；浏览列表不下载；失败／取消不覆盖当前选择；下载后断网重启仍可播放。检查一个较大的动画在目标 Android 设备上的内存和循环表现。清单大小测算不能替代这些产品验证。
